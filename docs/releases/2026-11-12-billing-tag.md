# 渠道计费标签

配合后端计费标签功能使用，详情见后端 `docs/billing-tag.md`。同一渠道类型下的不同渠道（例如 Vertex AI 的 Gemini 与 Claude）可以对同一用户设置不同折扣。标签只用于计费和统计，不影响选渠、重试和 Provider 绑定。前后端需要同时部署，无数据库迁移。

- 渠道表单新增可选的 Billing Tag 输入框，通过现有 config JSON 保存，统一存为小写，编辑时回显。输入时可联想其他渠道已有的标签，含非法字符时不提交，清空后删除该配置项。
- 编辑用户的 Additional discount 页签新增 Billing-Tag Discount 区，列出渠道上现有的标签。填了折扣就替代这些渠道的渠道类型折扣（两者不相乘），留空则沿用渠道类型折扣。用户配过但已没有渠道使用的标签单独标出，可以移除。Reset channel types 和批量设置只作用于渠道类型折扣。
- 管理员日志明细的折扣拆分里，用户渠道折扣来自标签时显示命中的标签。终端用户的日志和资料里没有标签。
- 管理员总览新增 Usage by source 卡片，按来源列出最近 24 小时的消耗：打了标签的渠道按标签归组，其余按渠道类型归组，已删除的渠道合并为一项，每项显示金额和占比。

折扣编辑器同时修了两个问题：

- 打开 Additional discount 页签后点 Save 没有反应，不发请求。原因是每一行折扣各自注册成表单字段，没填的行以 undefined 进入表单值，整份表单校验不通过。现在折扣区直接读写整个 `channel_ratios` 对象。
- 在折扣输入框里选中旧值再逐键输入新值会拼错（选中 0.85 输入 0.7 得到 0.857）。现在聚焦期间显示正在输入的文本，失焦后回到已生效的值。

发布前代码审查后的调整（折扣编辑器修好保存之后，这些问题才变得可达）：

- 折扣输入框里不可用的值（0、负数、没输完的数字）不再被悄悄丢弃：留在输入框并在该行提示，Save 被拦住，改对或清空后才能保存。原先会按旧值保存并跳走。
- 折扣可以填任意位数的小数。原先三位小数（如 0.875）会被浏览器的步长校验拦住。
- 批量设置框里按回车等同于 Apply，搜索框里按回车只筛选，都不再提交整个用户表单。批量设置或重置后各行立即显示新值。
- 名为 `constructor` 这类的标签可以正常列出和配置。库里计费不认的 key（包括名字不合法的 `tag:` 项）不再带回表单：名为 `target` 的 key 原先会让一次编辑清空全部折扣。
- 标签名和渠道类型 key 的识别口径与后端对齐（只接受 ASCII 字符，首尾空白的范围一致）。
- 渠道表单在没有任何配置项时提交 `{}` 而不是空串，清空标签不再依赖其他字段的默认值。
- 新增 `pnpm test:channel-ratios`。

对上面这批调整的第二轮复核后的修正：

- 折扣输入框（每一行和批量设置框）改为文本框，手机上仍弹出数字键盘。数字框的方向键、滚轮和步进箭头会按步长改值，上一批把步长放开之后一次改 1（0.85 按一次上箭头变成 1.85），改出来的是合法折扣，会直接生效并随 Save 保存。现在只认普通的十进制写法（`0.85`、`.85`），`1e3`、`0x10`、带正负号的写法都算无效；全角数字和句点、逗号按半角数字和小数点处理。
- `-`、`.` 这类没输完的内容可以正常删除。原先它们在数字框里读出来是空串，一步删空后这一行会卡在“空输入框加报错”，Save 一直被拦住。
- 还没改对的输入不再随输入框卸载而丢失。折扣页签切走后保持挂载：留着无效输入时在 Basic info 页签点 Save 会被拦住，并切回折扣页签显示是哪一行。留着未生效输入的渠道类型行不随搜索和 Customized only 隐藏（批量设置仍只作用于符合筛选的行，不会覆盖这样的行）。原先这两种情况下 Save 会按旧值提交，没有任何提示。
- 批量设置框里输入法上屏用的回车不再触发 Apply。
