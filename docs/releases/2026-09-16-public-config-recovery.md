# 站内文档与客户端 API 地址修复

删除通用设置中的 Docs address 输入、读取和提交，文档链接统一使用站内 `/docs`；旧页面兼容字段也固定为 `/docs`，忽略历史外部地址。

本次只读检查中，`https://api.linkinfra.ai/api/status` 与 `https://platform.linkinfra.ai/api/public/option` 均返回 200、版本 v0.1.24、`server_address=https://api.linkinfra.ai`。当前线上配置非空，未修改后端配置。无法从当前响应追溯截图时首次请求具体为何失败。

已确认并修复前端缺陷：一次配置请求失败或返回异常结构后，会将空对象和已完成 Promise 永久缓存，后续页面与弹窗不再重试。现改为仅短期缓存成功结果、失败可重新读取，共享更新全部使用者，并在网络恢复或重新聚焦时按需刷新。系统设置保存后强制刷新，若有更早的请求尚未完成，会在其结束后重新取新配置。

密钥页与客户端配置新增“重新读取 API 地址”，区分配置读取失败与后端实际未设置；失败期间不允许客户端导入。公开配置代理和请求禁用缓存。地址仍由 ServerAddress 生成：Claude Code 使用根地址，Codex 与 OpenAI 兼容客户端使用 `/v1`。

验证：

- 生产构建（含类型检查）通过。
- 配置恢复、并发去重、强制刷新、协议地址、模型传递和语言偏好共 13 项回归通过，文档站内入口定向测试通过。
- Edge 对公开新手指引页面模拟首次 HTTP 503、点击重新读取后恢复地址与复制按钮；检查旧 DocsAddress 被忽略、桌面和 390px 手机显示，无运行时异常。本次浏览器验证未访问受保护页面或修改账户。

本修复需要部署最新前端。部署前，刷新当前页面可清除旧版本的内存失败缓存，并重新尝试读取。
