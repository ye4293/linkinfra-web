# Playground remembered models and message deletion

- Model selections are remembered separately for chat and image mode, along with the last mode and the include-history switch. Preferences are saved immediately on selection in account-scoped browser localStorage and restored after navigation or refresh. API keys and session credentials are not part of this record. Available models are still checked against the current account's model list; an unavailable selection uses a valid fallback without erasing the remembered choice. A failed model-list request also leaves the preference intact.
- Every completed user message and Ola reply has a visible delete action next to copy. Confirmation identifies the message and removes only that entry, including its attachments, from the current mode's IndexedDB history. Other messages and the other mode remain intact. Users can remove several entries individually. Cancellation leaves history untouched; deletion is disabled during generation. Browser storage failures are surfaced because a deletion may otherwise reappear after refresh.
- Chat includes all remaining valid historical user/assistant messages and images by default, plus the system prompt and current input. It does not limit context to the immediately preceding turn. Error entries and empty placeholders are excluded. The include-history switch can send only the system prompt and current input; its setting now persists. Image generation/editing uses the current prompt and reference images, independently of chat history. Gateway/model context limits and request-size limits still apply; the app does not silently trim stored history.

Validation includes account-isolated preferences, invalid/newer saved records, storage failures, unavailable-model fallback, navigation and refresh restoration, multi-turn request inspection, deletion cancellation, deleting two individual entries and verifying subsequent request exclusion, reload persistence, deleting generated images while preserving chat history, disabled deletion during generation, and a 320px confirmation dialog without horizontal overflow. Browser checks use a local mock backend rather than paid upstream model calls.

All 82 repository tests, TypeScript, targeted lint and an isolated production build passed. Existing unrelated build notices remain unchanged. Deployed production behavior has not been verified by these local checks.
