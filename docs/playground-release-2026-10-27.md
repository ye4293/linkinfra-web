# Playground image support

- The main toolbar contains chat/image mode and model selection. API keys and mode-specific parameters live in the Settings drawer, on desktop and mobile. Chat and image histories are separate; labels follow the site language.
- Drop image files or browser image URLs onto the composer or conversation, paste screenshots, upload files, or add image URLs. Generated images can be reused directly with “Use as reference”. Attachments show previews and individual remove buttons. No image-enable switch is required. Up to 16 images, 20 MB each; PNG/JPEG/WebP for editing, plus GIF for chat.
- Image mode uses `/api/playground/images`: JSON forwards to `/v1/images/generations`; reference images use multipart `image[]` forwarded to `/v1/images/edits`. It supports size, quality, PNG/JPEG/WebP output and 1–4 images. GPT Image requests omit `response_format`. The proxy requires a session, validates parameters, strips the key from the body and forwards cancellation.
- Generated Base64 images support preview/download; URL results support preview/open original. For editing, remote reference URLs are fetched by the browser and need CORS access; users can download and drop the file if the image host blocks access. The server does not fetch user-supplied image URLs.
- Failed or cancelled requests retain the prompt and attachments. Chat accepts JSON fallback responses from gateways even when streaming was requested, handles split UTF-8 chunks and trailing SSE lines, and surfaces stream errors. A `[DONE]` event completes the request even if the upstream connection remains open. Streaming does not pull readers away from older messages. Enter while composing Chinese text does not send the prompt.

API reference: [OpenAI image generation guide](https://developers.openai.com/api/docs/guides/image-generation).

Validation: all 70 repository tests pass (`node --test scripts/test-*.cjs`, including 9 Playground tests), plus TypeScript, targeted Next.js lint, and an isolated production `next build` (existing warnings only). Browser checks cover direct drop, paste with text, attachment removal, separate histories, generation/edit requests, failure recovery, cancellation, IME input, and 1440px/1024px/768px/390px/320px layouts in both languages. Image parameter changes, reuse of generated images, preview closing, upload selection and reading history while streaming were also checked.

Live gateway check on 2026-10-27 (`https://api.linkinfra.ai`): `gpt-image-1.5` generated a 1024×1024 PNG in approximately 9 seconds and edited it in approximately 15 seconds. Both returned Base64. `gpt-image-1` appeared in the model list but its generation request returned HTTP 400, “The model 'gpt-image-1' does not exist.” This requires a gateway/channel configuration fix; the frontend prefers `gpt-image-1.5` when it is configured. A transient connection failure was also observed during testing. No test credentials are stored in the repository.
