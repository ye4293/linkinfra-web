# Playground request size compatibility

Vercel Functions reject request bodies larger than 4.5 MB before the route handler runs. The Playground accepts original images up to 20 MiB each; Base64 encoding and historical attachments can push chat JSON beyond the platform limit. Increasing a Next.js body-parser setting or function duration does not change this platform limit. See [Vercel Functions limits](https://vercel.com/docs/functions/limitations#request-body-size).

- Outgoing chat JSON and image-edit multipart requests use a 4,000,000-byte safety budget, including prompts, metadata, all historical inline images and multipart overhead. Small requests and remote chat image URLs remain unchanged.
- When needed, the browser compresses outgoing copies using WebP, preserving transparency, and reduces dimensions or quality until each image fits its share of the budget. Unsupported WebP encoders fall back to PNG. The model may receive less fine detail; originals used for previews and IndexedDB history are never replaced. Oversized GIFs produce an actionable error rather than being flattened.
- The composer shows preparation progress and supports cancellation. A notice confirms compression. Size failures and HTTP 413 responses show localized guidance and restore the submitted prompt and attachments.
- “Include chat history” is enabled by default. Disabling it sends only the system prompt and current message, with a visible composer reminder; existing local conversations remain saved. It does not delete or trim history.
- Full-resolution uploads beyond this limit require a separate direct-upload route to the gateway or object storage. This repair does not raise Vercel's limit or change response-size limits.

Validation: 79 repository tests cover request byte boundaries, UTF-8 accounting, unchanged small requests, cancellation, GIF handling and multipart prompt overhead, alongside existing Playground and application regressions. Browser checks use a local mock backend and a synthetic 2400 × 1800 PNG of 12,712,379 bytes. Two copies produce a 3,409,251-byte chat request and a 3,650,655-byte multipart edit request. Follow-up chat includes historical images within the budget; disabling history omits them. Original image data URLs remain unchanged after reload. Simulated HTTP 413 restores the draft and attachment without exposing the raw platform error. Cancelling preparation sends no API request and restores the input. These checks do not establish the status of the deployed production site.

TypeScript, targeted lint and an isolated production build passed. At a 390px viewport, the settings panel stays within the screen and there is no horizontal page overflow. The production build retains an existing unused-import warning in `components/icons.tsx`, an outdated Browserslist database notice and Node localStorage experimental warnings; no new Playground lint warnings were reported.
